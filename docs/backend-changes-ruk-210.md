# Бэковые изменения (ветка `feature/ruk-210`) — что поддержать на FE

Бэк реализовал схему первого пользователя (bootstrap-админ), invite-only signup
и убрал устаревший OAuth-флоу. Ниже — только то, что касается FE.

---

## 🔴 Требует доработки FE

### 1. `X-Test-Roles` — прокинуть через BFF (только dev)

**Зачем:** в dev OAuth-стаб создаёт нового пользователя на каждый логин → без
назначения роли он всегда `guest` (или случайно первый — `admin`). Чтобы в dev
тестировать admin/reviewer/editor-экраны через реальный логин, FE должен уметь
подсунуть роль новосозданному юзеру.

**Что сделать:** при обмене id_token (`exchangeGoogleIdToken` → `postBackendJson`,
файл `src/server/auth/backend-token-exchange.ts:31`, путь
`POST /api/v1/login/oauth/exchange/google`) добавлять HTTP-заголовок
`X-Test-Roles`, **только в dev-окружении**. Сейчас `postBackendJson` не принимает
доп-заголовки — сигнатуру придётся расширить.

**Контракт заголовка** (бэк: `internal/server/middlewares/test_roles.go`):

- Формат: `X-Test-Roles: admin,editor` — comma-separated.
- Пробелы триммятся, регистр не важен (`Admin` = `admin`), дубли схлопываются,
  пустое/отсутствующее значение = нет ролей.
- Валидные значения: `admin`, `editor`, `reviewer`, `guest`. Роль `system admin`
  запрещена.
- **Неизвестная роль → HTTP 400** (`invalid_role`). Не игнорится молча — весь
  exchange упадёт.
- Роли назначаются **только при создании** пользователя. Повторный логин тем же
  юзером роли НЕ меняет (логин не эскалирует привилегии).
- **Работает только в dev/local/performance_test.** В проде бэк-middleware
  физически отключена — заголовок игнорируется. Гейт на стороне FE тоже
  обязателен (не слать в prod-сборке).
- В публичный Swagger заголовок намеренно **не** вынесен — генератор FE-клиента
  его не покажет, добавлять руками через свой fetch-слой.

## 🟡 Изменения контракта — проверить согласованность (вероятно, уже ок)

### 2. Новый ответ логина: `403 signup_disabled`

При exchange неприглашённого пользователя (signup закрыт) бэк отвечает
**HTTP 403** с телом:

```json
{ "code": "signup_disabled", "message": "signup is disabled" }
```

(`internal/app/api/httperrors/mapper.go:82`)

- FE должен обработать этот код на логине (показать «регистрация закрыта / нужен
  инвайт», без утечки деталей).
- **UX-нюанс:** приглашённый, вошедший обычным логином вместо accept-ссылки
  инвайта, тоже получит этот generic 403 без подсказки. Дружелюбное сообщение —
  на стороне FE, если нужно.
- Свежая инсталляция: **первый** вошедший становится `admin` автоматически
  (bootstrap). Остальные — только по инвайту, либо `guest` если оператор включил
  `allow_open_signup`.

### 3. Удалён устаревший OAuth authorization-code флоу

Эндпоинты **`GET /api/v1/login/oauth/google`** и
**`GET /api/v1/login/oauth/google/callback`** удалены целиком (вместе с
HTML-handoff режимом и state/nonce-куками).

- FE и так на BFF/exchange (`POST /api/v1/login/oauth/exchange/google`) — этот
  путь **жив и не менялся**. Если в FE остались ссылки/редиректы на старые
  `login/oauth/google` — убрать.
- Куки `maintmode-refresh_token` и `maintmode-nonce` бэк больше не ставит и не
  читает. FE их и не использовал — просто подтверждение, что закладываться на них
  нельзя.

## 🟢 Уже совместимо (действий не требуется, для сверки)

- **refresh** (`POST /api/v1/refresh`): бэк читает `refresh_token` **из JSON-тела**
  (не из куки). FE уже шлёт `{refresh_token}` в теле
  (`backend-token-exchange.ts:76`) — **совпадает**.
- **logout / logout/all**: контракт не менялся (`Authorization: Bearer` +
  `{refresh_token}` в теле для logout) — FE уже так делает.
- **exchange, /me, /providers, invitation accept/preview**: контракты не тронуты.

---

**Итог:** реальная новая работа для FE — только пункт 1 (`X-Test-Roles` через BFF),
и это чисто dev-удобство, не прод-функциональность. Пункты 2–3 — проверка, что FE
не завязан на удалённое.
